# 调参核心代码审查（2026-10-17，dev）

本轮检查调参引擎、公式执行器、局部搜索、LLM 响应解析及相关桌面/硬件测试。以可复现的行为缺陷为依据，不凭代码外观判断作者或生成来源。

| 问题 | 原行为与影响 | 已做修改 |
| --- | --- | --- |
| 最后一轮仍买建议 | 普通 PID 用完测量预算后仍请求模型、写入新参数，最终参数缺少对应实测结果 | 最后一轮完成测量后保持参数；零剩余测量时不搜索、不请求、不做新的调参写入。退化回滚仍保留 |
| 本地计算显示为模型请求 | 在判断是否使用局部搜索之前就发出 `llm_request`，并提前拼装提示词 | 请求事件和提示词构造移到真正调用模型的位置 |
| 为迎合测试保留文本猜参 | 解析器含“为了防止测试用例失败”兜底；可能从思考、分析或损坏 JSON 内提取历史 PID | 仅接受显式 PID/Action/控制器区，或完整的裸 PID 三元组，避免把旧参数解释成建议 |
| JSON 多条提取路径且不理解字符串 | 正则加重复括号扫描；字符串中的括号会破坏边界，嵌套对象可能被作为独立建议 | 一次扫描处理字符串、转义和数组，保留父容器边界 |
| 数值清洗重复且不完整 | 顶层和子控制器各写一份清洗；布尔值被当作 0/1，超大整数可能触发异常 | 共用数值清洗，拒绝布尔参数并处理整数溢出及 JSON 数字解析错误 |
| 通用参数被默认成 PID 动作 | 模型返回 `parameters` 但省略动作时，默认 `ADJUST_PID` 导致公式路径拒绝本可用建议 | 按参数字段选择 `ADJUST_PARAMETERS`，保留后续边界和步长约束 |
| 公式深度限制依赖节点命名 | 遍历已排序节点时跳过深度累加，能接受超过声明上限的依赖链 | 按已计算的实际依赖层数检查 48 层边界，使用层数字典判断是否已访问 |
| 局部搜索被失败候选阻断 | 总先选预测最优项，再由调用者拒绝；其他可用候选也随之被放弃，可能增加模型调用 | 在生成候选时排除同目标下已失败的参数，共用参数签名，继续比较其他候选 |

回归测试保留暂停/停止、双环护栏、写入失败、用量归属等原意；需要调参写入的测试使用至少两轮测量预算，并提供写入后的遥测。新增覆盖解析歧义、超大整数、层数边界、失败候选替补及末轮零调用。

所有测试使用 `C:/Users/Administrator/conda-envs/matlab310/python.exe`，完整 `pytest -q` 结果为 **606 passed, 17 subtests passed**（89.43 秒）。本次没有调用收费模型，也没有执行新的真实 MATLAB/物理硬件实验；相关自动化覆盖使用模拟环境和传输替身。

这些修改能消除相应条件下的一次无效末轮请求、减少重复候选预演，并阻止错误参数解析。实际 Token、费用和收敛轮数改善仍需真实模型及目标系统的对照实验。本报告不是全仓库无缺陷或任意阶控制器适用性的保证。
